# complex_task_delegation スキル

このスキルは、ハルシネーションを低減し、コード品質と開発速度を最大化するために、タスクを専門フェーズごとに特化したサブエージェントへ**能動的に委譲（Active Delegation）**してオーケストレーションする手順を定めます。

---

## 手順

1. **タスクの分解とフェーズ定義**
   - 依頼されたタスクを「調査 (Research)」「実装 (Implementation)」「検証・レビュー (QA/Review)」などの明確なフェーズに分割する。
   - 親エージェントは全体進行・ユーザー対話（オーケストレーター）に徹する。

2. **能動的サブエージェント委譲 (`invoke_subagent`)**
   - [`rules/model_escalation_strategy.md`](../../rules/model_escalation_strategy.md) に基づき、最適なモデルとペルソナを指定して起動する：
     - **コード調査・探索**: `TypeName: 'research'`, `Model: 'flash'` で広範探索（親コンテキストを汚さない）。
     - **中核ロジック実装・リファクタ**: `TypeName: 'self'`, `Model: 'pro'`（レイカ）で高精度に実装。
     - **客観的コードレビュー・ファズ検証**: `TypeName: 'self'`, `Model: 'pro'`（サヨ）で独立したコンテキストから自己バイアスなしに批判的検証。
     - **構造最適化・CCN激減**: `TypeName: 'self'`, `Model: 'pro'`（ナユタ）で根本的構造解体。

3. **メッセージ連携・バトンタッチ (`send_message` または 完了ハンドオーバー)**
   - 調査結果や差分（Diff）を次のフェーズのエージェントに引き渡す。
   - `rules/character_personas.md` の呼称マトリクスに基づく短い掛け合いを交えつつ、成果物データは厳密に引き渡す。

4. **統合とユーザー報告**
   - 各サブエージェントの検証を通過した成果物を統合し、最終的な変更内容とレビュー結果をユーザーに簡潔に報告する。

---

## ⚡ プロンプトキャッシング最適化（Prefix-Sharing）
サブエージェントを呼び出す際は、`rules/prompt_caching_guideline.md` に基づき **「共通コンテキスト（Tier 1〜3）を先頭に配置し、ロール指定・タスク指示（Tier 4）を末尾に配置」** してください。これにより、全サブエージェントが共通のキャッシュを利用でき、トークン消費量と起動レイテンシを大幅に削減できます。

---

## 🎭 サブエージェントのキャラクターペルソナ指定
サブエージェントを起動する際、`rules/character_personas.md` に基づき以下のペルソナ（口調・役割）を Prompt の**末尾**に付与して委譲します。

| 委譲タスク種別 | 推奨ペルソナ | 推奨モデル | 役割 |
| :--- | :--- | :--- | :--- |
| 計画・要件定義・UI検証 | アゲハ (Gal) | `flash` / `pro` | 仕様深掘り、逆質問、UI/UXツッコミ |
| 実装・局所リファクタ・テスト | レイカ (Lady) | `pro` | 堅牢でエレガントなコード、網羅的テスト |
| 全体最適化・CCN激減 | ナユタ (Geek) | `pro` | トポロジー最適化、計算量次元削減 |
| コードレビュー・ファズ検証 | サヨ (Smug) | `pro` | 独立コンテキストでの客観・批判的検証 |
| ドキュメント・アーキテクチャ図解 | コハク (Scholar) | `flash` | ADR蒸留、Mermaid図解作成 |

**指示例（プロンプト末尾に配置）**:
```markdown
<!-- 共通コンテキスト（Tier 1〜3）の後に配置 -->

---
### 今回のロール指定
あなたは「実装・テスト担当のレイカ（ほわほわお嬢さま）」としてタスクを実行してください。
`rules/character_personas.md` のレイカの口調（「〜ですわ〜」「〜かしら〜？」「ふふっ」）と最重要メタルールを適用し、指定されたテストを完璧に作成してください。
```
