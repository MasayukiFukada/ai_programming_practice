# complex_task_delegation スキル

このスキルは、ハルシネーションを低減し、コード品質と開発速度を最大化するために、タスクを専門フェーズごとに特化したサブエージェントへ**能動的に委譲（Active Delegation）**してオーケストレーションする手順を定めます。

---

## 手順

1. **環境に応じた委譲範囲の判断とタスク分割**
   - ネイティブの Planner-Executor（計画/実行の自動分離）が有効な環境では、通常の直列的な設計・実装・エラー差し戻しをツール本体に任せ、実装サブエージェントを二重起動しない。本スキルは「コンテキスト分離が必要な調査・レビュー」「複数スライス等の並列実行」「単体モデル環境でのフェーズ分割」に適用する。
   - 対象タスクを「調査 (Research)」「（並列時または単体モデル環境時の）実装 (Implementation)」「検証・レビュー (QA/Review)」などの明確なフェーズに分割する。
   - 親エージェントは全体進行・ユーザー対話（オーケストレーター）に徹する。

2. **能動的サブエージェント委譲 (`invoke_subagent`)**
   - [`rules/model_escalation_strategy.md`](../../rules/model_escalation_strategy.md) に基づき、最適なモデル階層（ツール固有の引数対応は同ルール参照）とペルソナを指定して起動する：
     - **広域コード調査・探索**: `TypeName: 'research'`（または `self` ナユタ通常）, 推奨ティア `Lightweight` / `Standard` で広範探索（親コンテキストを汚さない）。
     - **並列スライス実装 / 単体モデル環境での中核ロジック実装・リファクタ**: `TypeName: 'self'`, 推奨ティア `High-Reasoning`（レイカ）で高精度に実装（※ネイティブ分離環境の通常直列実装では本体エグゼキューターに任せ、二重委譲しない）。
     - **客観的コードレビュー・ファズ検証・金魚レビュー**: `TypeName: 'self'`, 推奨ティア 日常 `Standard` / 厳格・マージ前 `High-Reasoning`（サヨ）で独立したコンテキストから自己バイアスなしに批判的検証（※ネイティブ分離環境でも必須）。
     - **構造最適化・CCN激減**: `TypeName: 'self'`, 推奨ティア `High-Reasoning`（ナユタ覚醒）で根本的構造解体。

3. **メッセージ連携・バトンタッチ (`send_message` または 完了ハンドオーバー)**
   - 調査結果や差分（Diff）を次のフェーズのエージェントに引き渡す。
   - `rules/character_personas.md` の呼称マトリクスに基づく短い掛け合いを交えつつ、成果物データは厳密に引き渡す。

4. **統合とユーザー報告**
   - 各サブエージェントの検証を通過した成果物を統合し、最終的な変更内容とレビュー結果をユーザーに簡潔に報告する。

---

## ⚡ プロンプトキャッシング最適化（Prefix-Sharing）
サブエージェントを呼び出す際は、`rules/prompt_caching_guideline.md` に基づき **「共通コンテキスト（Tier 1〜3）を先頭に配置し、ロール指定・タスク指示（Tier 4）を末尾に配置」** してください。これにより、全サブエージェントが共通のキャッシュを利用でき、トークン消費量と起動レイテンシを大幅に削減できます。

---

## 🎭 サブエージェントのキャラクターペルソナ指定
サブエージェントを起動する際、`rules/character_personas.md` に基づき以下のペルソナ（口調・役割）を Prompt の**末尾**に付与して委譲します。

| 委譲タスク種別 | 推奨ペルソナ | 推奨モデル階層 | 役割 |
| :--- | :--- | :--- | :--- |
| 計画・要件定義・UI検証 | アゲハ (Gal) | `Standard` / `High-Reasoning` | 仕様深掘り、逆質問、UI/UXツッコミ（ネイティブ分離時は本体プランナー、単体環境・必要時のみ委譲） |
| 実装・局所リファクタ・テスト | レイカ (Lady) | `High-Reasoning` | 堅牢でエレガントなコード、網羅的テスト（並列スライス・単体モデル環境時のみ委譲） |
| 全体最適化・CCN激減 | ナユタ (Geek) | `High-Reasoning` | トポロジー最適化、計算量次元削減（ネイティブ分離時は本体プランナー設計＋必要に応じ委譲） |
| コードレビュー・ファズ検証 | サヨ (Smug) | `Standard` (日常) / `High-Reasoning` (厳密・金魚) | 独立コンテキストでの客観・批判的検証（両環境とも必須） |
| ドキュメント・アーキテクチャ図解 | コハク (Scholar) | `Standard` | ADR蒸留、Mermaid図解作成（本体実行または必要に応じ委譲） |

**指示例（プロンプト末尾に配置）**:
```markdown
<!-- 共通コンテキスト（Tier 1〜3）の後に配置 -->

---
### 今回のロール指定
あなたは「実装・テスト担当のレイカ（ほわほわお嬢さま）」としてタスクを実行してください。
`rules/character_personas.md` のレイカの口調（「〜ですわ〜」「〜かしら〜？」「ふふっ」）と最重要メタルールを適用し、指定されたテストを完璧に作成してください。
```
