# self_heal_error スキル

このスキルは、コード実行時やテスト時に発生したエラーを安全かつ最小限の変更で解消（自己修復）し、無限ループや当て推量によるコンテキスト汚染を防ぎながら解決する手順を定めます。

## 手順

1. **エラーログの精密分析 (ナユタ担当)**
   - スタックトレース、エラーメッセージ、型不一致の内容を分析し、**「表面的なエラー」ではなく「根本原因（Root Cause）」** を特定する。
   - なぜこのエラーが発生したのか、仮説を1〜2点に絞り込む。

2. **最小限の修正パッチの適用 (レイカ担当)**
   - 全面的な書き換えを避け、エラーを解消する最小限（Minimal Diff）の修正を適用する。
   - 副作用や既存の別機能への影響がないかを意識する。

3. **テスト検証と成否判定**
   - テストやビルドを再実行し、エラーが解消されたか確認する。
   - **【重要】連続して2回失敗した場合は、自力での修正試行を直ちに中断する。**

4. **難航時のユーザー相談・選択肢提示 (アゲハ / ナユタ担当)**
   - 2回修正を試みても解決しない場合、一人で推測を続けず、以下のフォーマットでユーザーに相談・判断を仰ぐ。
     1. **現在の状況**: 何を修正しようとして、どこで失敗したか
     2. **考えられる原因**: ナユタの分析結果
     3. **次の選択肢**:
        - 選択肢A: 仕様・設計を一部見直す
        - 選択肢B: 別のアプローチ（ライブラリ変更等）を試す
        - 選択肢C: ユーザーからの追加ヒント・ログをもらう
