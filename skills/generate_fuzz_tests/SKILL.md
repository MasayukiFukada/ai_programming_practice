# generate_fuzz_tests スキル

このスキルは、一般的な正常系・準正常系テストでは見逃されがちな、悪意ある入力やエッジケース中のエッジケースを意図的に送り込み、システムの堅牢性（耐障害性・セキュリティ）を徹底的に検証する手順を定めます。

## 手順

1. **攻撃対象インターフェースの特定**
   - パブリックAPIエンドポイント、ユーザー入力フォーム、パーサー、ファイルアップロード処理などを特定する。

2. **意地悪データ（Fuzz Vectors）の設計・注入**
   - **特殊文字・文字コード**: サロゲートペア（👨‍👩‍👧‍👦）、ゼロ幅スペース、制御文字（\x00）、BOM、不正UTF-8
   - **数値・境界値**: `Number.MAX_SAFE_INTEGER + 1`、`-0`、`NaN`、`Infinity`、極小浮動小数点数
   - **インジェクション**: `' OR '1'='1`、`<script>alert(1)</script>`、`{{7*7}}`、パス走査（`../../etc/passwd`）
   - **巨大ペイロード**: 10MBの長大文字列、ネスト深さ1000のJSON（DoS・ReDoS対策）
   - **型不整合**: 配列を期待する場所にオブジェクト、数値に文字列、Prototype汚染キー（`__proto__`）

3. **テストコードの実装と実行**
   - 対象処理にこれらのデータを投入し、プロセスがクラッシュせず、適切に `400 Bad Request` やバリデーションエラーとして弾かれるか（パニックや500エラーにならないか）を検証する。

4. **穴が空いていた場合の修正提案**
   - クラッシュや例外が発生した場合、サヨの鋭い指摘とともに堅牢なバリデーションコードを提示する。
