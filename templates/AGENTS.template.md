## コーディング規約（Coding Style Guidelines）

- **アーキテクチャ**: Vertical Slice Architecture( 各コンテキストの範囲を絞る )を採用。
    - オブジェクト指向よりも関数型( FP )をベースとする
- **スタイル**:
    - 関数は抽象レベルを揃え、1つの関数は短く保つ。
    - フォーマットと静的解析を遵守する。
- **テスト**: 
    - ドメインロジック、ユースケースについてはテストコードを作成する。
    - 画面に関するテストコードは不要とする。


## セキュリティ（Security considerations）

- サーバーポート、DBパス等の設定は環境変数（`.env`）で管理する。
- 開発中は .env も読み書きして良い
- リポジトリに機密情報（秘密鍵、APIキー等）を含めない。

## メンテナンス・ポリシー（Maintenance policy）

- ファイルが増える場合などは `.gitignore` をメンテナンスする（特に `LOCAL_*.md` や `local_*.md` を除外）。
- ドキュメントは `docs/` 配下に Markdown 形式( Open Knowledge Format )で残す。
- 変更を加える際は `PLAN.md` を更新し、進捗を管理する。
- ローカル専用のAIコンテキストは `LOCAL_CONTEXT.md`（仕様・不変）と `LOCAL_LOG.md`（作業ログ・追記型）に分離して管理する。

## クイックコマンド（一言ショートカット指示）

※ 本プラグインを取り込んでいる場合、`rules/quick_commands.md` の定義が自動適用されます。
プロジェクト固有でコマンドを上書き・追加したい場合、または独自の一言指示を定義したい場合は本セクションに記述してください。

ユーザーがチャットで以下の単語を一言のみ（または短いフレーズ）で発言した場合、即座に対応する定型処理を実行してください。
特に **「ヘルプ」** と入力された場合は、利用可能なクイックコマンドの一覧を案内してください。

| 入力キーワード | 実行する定型処理 | 備考・コマンド例 |
| :--- | :--- | :--- |
| **「ヘルプ」** / **「help」** | 登録されているクイックコマンドの一覧と簡単な使い方を出力する。 | 本一覧表をわかりやすく案内 |
| **「環境」** / **「env」** | プロジェクトの環境を調査し、結果を報告する。 | （例: `.gitignore` の不足 / `環境変数の管理方法` など） |
| **「ビルド」** / **「build」** | プロジェクトのビルドコマンドを実行し、結果を報告する。 | （例: `npm run build` / `cargo build` など） |
| **「テスト」** / **「test」** | テストを実行し、失敗があれば原因解析と修正案を提示する。 | （例: `npm test` / `pytest` など） |
| **「カバレッジ」** / **「coverage」** | カバレッジを実行し、コードのカバレッジの改善案を提示する。 | カバレッジ環境の整備も含む |
| **「チェック」** / **「lint」** | 静的解析（型チェック・Linter）を実行し、問題点を報告する。 | （例: `npm run lint` / `cargo check` / `CCN 計測` など） |
| **「リファクタ」** / **「refactor」** | 純粋関数化、CCN低減、テスタビリティ向上を目的としたリファクタ案を提示する。 | レイカ（実装・局所リファクタ担当）起動 |
| **「最適化」** / **「optimize」** | 全体俯瞰、CCN激減、ボトルネック・計算量最適化などの改善案を提示する。 | ナユタ（全体最適化・CCN改善担当）起動 |
| **「セキュリティ」** / **「security」** | セキュリティチェックを実行し、潜在的な脆弱性や不正入力を診断する。 | （例: `SQLi / XSS / 不正な型入力` など） |
| **「レビュー」** / **「review」** | `git diff` を確認し、コードレビュー・品質チェックを実行する。 | サヨ（レビュー担当）起動 |
| **「解説」** / **「spec」** | 現在のコードや機能の解説・仕様ドキュメントを作成する。 | コハク（ドキュメント担当）起動 |
| **「要約」** / **「context」** | 決定事項・実装内容をまとめ、次回再開用サマリー（`LOCAL_LOG.md` 末尾追記用）を出力する。 | トークン節約・引き継ぎ用 |
| **「おまかせ」** / **「any」** | フォーマット適用、テスト実行、ビルド確認を一括で行う。 | 一連のクリーンアップ処理 |
