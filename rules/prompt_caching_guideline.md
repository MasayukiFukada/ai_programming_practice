# プロンプトキャッシング＆トークン最適化ガイドライン (Prompt Caching Guideline) [DRAFT]

> [!NOTE]
> **【ステータス: ドラフト】**
> 本ガイドラインは現在検証・ドラフト段階です。実際の運用結果に応じて順次ブラッシュアップされます。
> サブモジュール（プラグイン）として取り込み先のプロジェクトでは、必要に応じてルールを参照・適用してください。

本ドキュメントは、LLM（Gemini, Claude, OpenAI等）の **プロンプトキャッシング（Prompt Caching / コンテキストキャッシング）** を最大限に活用し、トークン消費量とコストを削減しながら応答速度を向上させるための運用ルールと設計指針を定めます。

---

## 1. 基本原則：Prefix-First（静的情報を先頭に固定）

LLMのプロンプトキャッシングは、基本的に **「プロンプトの先頭から完全一致しているトークン列」** に対して適用されます。
そのため、更新頻度が低い「静的情報」を上部に、毎回変化する「動的情報」を下部に配置します。

```text
┌────────────────────────────────────────────────────────┐
│ 1. システムプロンプト / 役割定義 (不変)                  │ ──┐
├────────────────────────────────────────────────────────┤   │
│ 2. プロジェクト共通ルール / コーディング規約 (不変)      │   │ キャッシュ対象
├────────────────────────────────────────────────────────┤   │ (高ヒット率)
│ 3. プロジェクト仕様 / 型定義 / スキーマ (準不変)        │ ──┘
├────────────────────────────────────────────────────────┤
│ 4. 会話履歴 (同一セッション内で蓄積)                    │ ─── ターン内でキャッシュ
├────────────────────────────────────────────────────────┤
│ 5. 今回のタスク / エラーログ / ユーザー入力 (可変)       │ ─── 毎回変化 (末尾)
└────────────────────────────────────────────────────────┘
```

> **禁止事項**: 先頭に動的な値（現在日時、セッションID、ランダムUUIDなど）を埋め込まないでください。先頭が1文字でも変わると、後続のすべてのキャッシュが無効化されます。

---

## 2. 個人開発・プロジェクトでのローカルコンテキスト運用

プロジェクト固有の背景やアーキテクチャ情報をAIに毎回渡す場合、`templates/LOCAL_CONTEXT.template.md` を元にローカル用コンテキストファイルを作成して運用します。

### ① `LOCAL_CONTEXT.md` の作成とGit除外
- `templates/LOCAL_CONTEXT.template.md` をプロジェクトルートに `LOCAL_CONTEXT.md` としてコピーします。
- プロジェクトの `.gitignore` に追加し、個人の作業用設定や特定環境の情報をGitにコミットしないようにします。

```gitignore
# ローカル用AIコンテキスト
LOCAL_CONTEXT.md
.gemini/rules/local_*.md
```

### ② ファイル更新の抑制（キャッシュの保護）
- `LOCAL_CONTEXT.md` や `rules/` 配下のファイルは、**1文字・1行の変更でもキャッシュが破棄** されます。
- 一時的なTODOやメモは `LOCAL_CONTEXT.md` に書かず、チャット末尾のユーザープロンプトとして入力してください。
- ファイルの更新は「機能完成時」「設計見直し時」など、区切りの良いタイミングにまとめて行います。

---

## 3. チャットセッション（会話ライフサイクル）の管理

### ① 同一タスクは同じセッションでテンポよく進める
- 同一セッション（マルチターン会話）内では、過去の会話履歴がキャッシュとして再利用されるため、2往復目以降の入力コストが大幅に下がります。
- 関連する作業（例: あるAPIエンドポイントの実装とテスト作成）は同じセッション内で完結させます。

### ② タスク完了時はセッションをリフレッシュ（新規作成）する
- 会話が長くなりすぎると、全体のトークン数（累積コンテキスト長）自体が肥大化し、キャッシュ割引があってもコストやレイテンシが増大します。
- 1つの機能や調査が完了したら、新しいセッション（新規チャット）を立ち上げてリフレッシュしてください。

## 4. プロンプト入力時のテンプレート（実例）

AIに指示を出す際は、以下の構造を意識して送信します。

```markdown
<!-- 【固定部】LOCAL_CONTEXT.md を参照させるか、冒頭に配置（キャッシュ有効） -->
[LOCAL_CONTEXT.md の内容]

---

<!-- 【可変部】今回の指示・動的データ（末尾に配置） -->
### 今回のタスク
- 対象ファイル: `src/features/auth/login.ts`
- 目的: ログイン処理のバリデーションを追加する
- 発生しているエラー / 要件:
  ```text
  [エラーログや具体的な変更要件をここに記述]
  ```
```
