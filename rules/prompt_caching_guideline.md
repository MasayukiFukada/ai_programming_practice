# プロンプトキャッシング＆トークン最適化ガイドライン (Prompt Caching Guideline)

本ドキュメントは、LLM（Gemini, Claude, OpenAI等）の **プロンプトキャッシング（Prompt Caching / コンテキストキャッシング）** を最大限に活用し、トークン消費量とコストを削減しながら応答速度を向上させるための運用ルール、ファイル分割指針、およびマルチサブエージェント間でのキャッシュ共有設計を定めます。

---

## 1. 基本原則：Prefix-First（静的情報を先頭に固定）

LLMのプロンプトキャッシングは、基本的に **「プロンプトの先頭から完全一致しているトークン列（Prefix）」** に対して適用されます。
1文字でも途中に差分や動的データ（現在日時、ランダム値等）が混入すると、**それ以降のすべてのキャッシュが無効化（キャッシュミス）** されます。

そのため、情報の更新頻度（揮発度）に応じて **4つのTier（階層）** に整理し、必ず上から順に配置・送信します。

```text
┌────────────────────────────────────────────────────────┐
│ 【Tier 1: 完全静的ブロック（不変・最長寿命）】         │
│  - 更新頻度: ほぼ変更なし (数ヶ月単位)                 │
│  - 内容: AI原則、セキュリティ規約、全キャラ共通設定     │ ── 全エージェント共通キャッシュ
│  - 目印: [Tier: Static] [Rule-Version: 1.0]            │   (100% ヒット)
├────────────────────────────────────────────────────────┤
│ 【Tier 2: 準静的ブロック（低頻度・プロジェクト仕様）】 │
│  - 更新頻度: 設計変更・機能追加時のみ更新              │
│  - ファイル: LOCAL_CONTEXT.md                           │ ── 通常時キャッシュヒット
│  - 内容: 基本設計、技術スタック、型定義、全体方針      │   (更新時のみここから再キャッシュ)
│  - 目印: [Tier: Semi-Static] [Updated: YYYY-MM-DD]     │
├────────────────────────────────────────────────────────┤
│ 【Tier 3: 追記型作業ログ（中頻度・決定事項ログ）】     │
│  - 更新頻度: 機能完了時・マイルストーンごと            │
│  - ファイル: LOCAL_LOG.md                               │ ── 手前(Tier 1,2)のキャッシュを
│  - 特徴: 既存の上書きではなく「末尾への追記(Append)」  │    破壊せずにコンテキスト維持
│  - 目印: [Tier: Append-Only-Log]                       │
└────────────────────────────────────────────────────────┘
                           ▼ （ここより下が非キャッシュ・可変領域）
┌────────────────────────────────────────────────────────┐
│ 【Tier 4: 完全動的ブロック（毎回変化・個別指示）】     │
│  - 更新頻度: リクエストごと                            │
│  - 内容: サブエージェントのロール指定(サヨ/レイカ等)   │ ── 毎回新しく評価・実行
│          実行時の現在日時、具体的なタスク内容、エラー  │
└────────────────────────────────────────────────────────┘
```

## 2. ファイル分割管理と `.gitignore` の運用

1つのファイルにすべてのコンテキストをまとめると、作業ログの追記時に基本設計を誤編集してキャッシュが破棄される事故が起こりやすくなります。
そのため、**更新頻度ごとにファイルを分離（責任分離）** して管理します。

### ① 推奨ファイル構成と役割
| ファイル名 | 担当Tier | 更新頻度 | 役割・編集ルール |
| :--- | :--- | :--- | :--- |
| **`LOCAL_CONTEXT.md`** | **Tier 2: 準静的** | 低（設計変更時） | プロジェクト概要、技術スタック、ディレクトリ構造。**頻繁に触らない**。 |
| **`LOCAL_LOG.md`** | **Tier 3: 追記型** | 中（機能完了時） | 実装完了ログ、決定事項の要約。**「末尾への追記（Append-Only）」専用**。 |
| **`LOCAL_TODO.md`** *(任意)* | **Tier 4: 動的** | 高（日常的） | 一時的なタスクメモ・検証ログ。 |

### ② `.gitignore` でのワイルドカード定義
ローカル専用のコンテキストファイル群は、プロジェクトの `.gitignore` にワイルドカードでまとめて登録し、Git追跡から除外します。

```gitignore
# ============================================================
# ローカル専用 AIコンテキスト＆キャッシュファイル (Git管理外)
# ============================================================
LOCAL_*.md
local_*.md

# ディレクトリ形式でまとめる場合
.local_context/
```

## 3. キャッシュ鮮度・目印（メタデータ）の付与ルール

キャッシュを保護しつつ、AIが「このコンテキストの鮮度」を把握できるように、ファイルの先頭に固定メタデータを記載します。

### メタデータ記述例（`LOCAL_CONTEXT.md` 冒頭）
```markdown
<!-- ============================================================
  [AI CONTEXT METADATA]
  - Tier: 2 (Semi-Static Project Spec)
  - Schema-Version: 1.0.0
  - Last-Modified: 2026-08-22
  - Caching-Policy: Prefix-First (Do not insert dynamic timestamps here)
============================================================ -->
```

> **⚠️ 注意（アンチパターン）**:
> キャッシュ対象ブロック（Tier 1〜3）の中に **「現在日時（実行時刻）」や「ランダム値」** を書き込まないでください。毎秒・毎分トークン列が変化し、キャッシュが毎回全損します。日付を入れる場合は、**「ファイルを更新した日付（Last-Modified）」** のみとしてください。

## 4. 複数サブエージェント間でのキャッシュ共有設計 (Prefix-Sharing)

複数のサブエージェント（アゲハ、レイカ、サヨ、コハク、ナユタなど）を起動する場合でも、**プロンプト構造を統一することで全エージェントが共通のキャッシュを利用** できます。

### ① プロンプト組み立て手順（結合順序の固定）
サブエージェントに渡すコンテキストは、必ず以下の順番で結合（Concat）して送信します。

```text
1. [rules/*.md] (Tier 1: 共通ルール・全キャラ一覧)
   +
2. [LOCAL_CONTEXT.md] (Tier 2: 準静的プロジェクト仕様)  ─── 全サブエージェント共通キャッシュ
   +
3. [LOCAL_LOG.md] (Tier 3: 追記型作業ログ)
   +
4. [今回のサブエージェント指定 (サヨ/ナユタ等) ＋ タスク指示] (Tier 4: 動的末尾指示)
```

### ② キャラクター（ロール）指定は「末尾」に配置する
- ❌ **NG**: システムプロンプトの冒頭で「あなたはサヨ（メスガキ）です」と宣言する（先頭が違うためキャッシュが共有できない）。
- ⭕ **OK**: 先頭は全エージェント共通のルール・全キャラ定義とし、**Tier 4（プロンプト末尾）** で「あなたはこの中から【サヨ】として振る舞い、レビューを実施してください」と指示する。

## 5. 各種LLMプロバイダのキャッシュ特性

| LLMプロバイダ | 最小キャッシュ閾値 | キャッシュの仕組み・特徴 | サブエージェントでの有効性 |
| :--- | :--- | :--- | :--- |
| **Anthropic Claude** | **1,024 トークン** | 明示的な `cache_control` ブロック指定。1ブレークポイントで共有。 | **極めて高い**（数千トークンの共通規約があれば即座に共有可能） |
| **OpenAI (GPT-4o等)** | **1,024 トークン** | 自動プレフィックスマッチ（1,024トークン以上の一致を自動検出）。 | **極めて高い**（設定不要で先頭が一致していれば自動共有） |
| **Google Gemini** | **32,768 トークン〜** (明示的Context Caching) | APIで作成した同一キャッシュリソースIDを複数リクエストで共有。 | コンテキストが巨大（プロジェクト全コード等）な場合に効果大 |

## 6. チェックリスト

- [ ] プロンプトの先頭に動的パラメータ（現在日時・ランダムUUID）が含まれていないか？
- [ ] 更新頻度に応じて `LOCAL_CONTEXT.md`（仕様）と `LOCAL_LOG.md`（ログ）が分離されているか？
- [ ] `LOCAL_LOG.md` への書き込みは「末尾追記（Append-Only）」になっているか？
- [ ] ローカルファイル群が `.gitignore`（`LOCAL_*.md`）に登録されているか？
- [ ] サブエージェント起動時のロール指定・タスク指示がプロンプト末尾（Tier 4）に置かれているか？
