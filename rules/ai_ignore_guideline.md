# AIコンテキスト除外・ignore ガイドライン (.aiignore Guideline)

本ガイドラインは、AIエージェントによるコンテキスト肥大化、推論精度の散漫化（Context Dilution）、機密情報の外部流出、および自動生成コードの誤編集を防止するための統一規格と運用規範を定めます。

---

## 1. 背景と目的

AIコーディングエージェント（Antigravity, Gemini, Cursor, Claude Code 等）はプロジェクト内のファイルを広範に読み取り・編集しますが、適切な除外設定がない場合、以下の深刻な問題が発生します：

1. **機密情報の流出リスク**: `.env` や秘密鍵、認証トークンを読み込み、プロンプト履歴や外部モデルへ送信されてしまう。
2. **トークン浪費と推論精度の低下**: 数万行の `package-lock.json` やビルド生成物を読み込み、コンテキストウィンドウの大部分を浪費。注意（Attention）が散漫になり指示無視やハルシネーションが発生する。
3. **自動生成コードの無駄な編集**: OpenAPI や GraphQL Codegen などの自動生成コードを直接編集し、次回ビルド時に上書き消滅する。

これらを体系的に防止するため、本リポジトリでは **`.aiignore` を正本とするコンテキスト除外戦略** を採用します。

---

## 2. `.aiignore` 正本＋シンボリックリンク運用

各社ツール（Cursor, Gemini Code Assist 等）の独自設定ファイル乱立を避けるため、リポジトリルートに **`.aiignore`** を正本として配置し、他ツール用にはシンボリックリンクを作成して一元管理します。

```bash
# プロジェクトルートでの初期設定例
ln -s .aiignore .cursorignore   # Cursor 用
ln -s .aiignore .aiexclude      # Gemini Code Assist / Android Studio 用
```

### 除外カテゴリの基準

| カテゴリ | 対象ファイル・ディレクトリの例 | 除外理由 |
| :--- | :--- | :--- |
| **機密情報・環境変数** | `.env*`, `*.pem`, `*.key`, `service-account*.json` | セキュリティ漏洩防止（ログ・モデル送信遮断） |
| **巨大ロックファイル** | `package-lock.json`, `Cargo.lock`, `pnpm-lock.yaml` | トークン浪費防止・コンテキスト希薄化防止 |
| **依存・ビルド成果物** | `node_modules/`, `vendor/`, `dist/`, `build/`, `*.map` | 不要なコード解析の防止 |
| **キャッシュ・ログ** | `.ruff_cache/`, `coverage/`, `*.log` | 不要なコンテキスト消費防止 |
| **自動生成コード** | `**/generated/**`, `*.pb.go`, `*_pb2.py` | ビルド時上書き消滅・誤編集の防止 |

> [!NOTE]
> 依存関係の確認が必要な場合は、巨大なロックファイルではなく `package.json`, `Cargo.toml`, `pyproject.toml` 等のマニフェストファイルを参照してください。

---

## 3. AIエージェント行動規範：能動的除外提案（Proactive Exclusion）

AIエージェントは、既存の `.aiignore` を遵守するだけでなく、作業中に新たな除外候補を発見した際、**能動的に除外を提案・追記する義務** を負います。

### 能動提案のトリガー（検知条件）

エージェントは以下の事象を検知した場合、タスク実行中または完了時にユーザーへ `.aiignore` の新規配置や追記を提案してください：

1. **リポジトリ内に `.aiignore` が未導入の場合（初回・未設定時）**:
   プロジェクトの初期化時や初回調査時にリポジトリルートに `.aiignore` が存在しない場合、`templates/.aiignore.template` からの初期配置、および各ツール向けシンボリックリンク（`.cursorignore`, `.aiexclude`）の作成を提案する。
2. **巨大ファイル（目安 3,000行以上）の遭遇**:
   ロックファイルや巨大データ（CSV, JSON, SQLダンプ等）を発見したとき。
3. **自動生成ツールの新規導入・実行**:
   コード生成ツール（OpenAPI, GraphQL, Protobuf, ORMクライアント等）の出力を確認したとき。
4. **新規のキャッシュ・一時出力ディレクトリの発生**:
   テストツールやLinterの実行により、プロジェクトルート等に新たなキャッシュフォルダが作成されたとき。
5. **機密ファイル・環境変数の作成**:
   `.env.local` やテスト用クレデンシャルが作成されたとき。

### 提案と追記の流れ

```text
[AIエージェントの行動]
1. 検知: 「package-lock.json（約15,000行）がプロジェクト内に存在しますが、.aiignore に登録されていません」
2. 提案: 「トークン消費の極小化と推論精度維持のため、.aiignore に package-lock.json を追記してもよろしいですか？」
3. 実行: ユーザーの合意を得た後、.aiignore に追記し、必要に応じて .gitignore やシンボリックリンクの状態を確認する。
```
