# バージョン管理システム（VCS）優先ルール: Jujutsu (jj) 優先ガイドライン

本ガイドラインは、プロジェクトにおけるバージョン管理ツールとして **Jujutsu (`jj`)** が導入されている環境において、AIエージェントが Git コマンドよりも Jujutsu コマンドを最優先で使用するための行動規範を定めます。

---

## 1. 検出と判定条件 (Detection)

エージェントは、VCS関連のコマンドを実行または提案する前に、以下のいずれかの条件で Jujutsu リポジトリであるかを判定します。

1. カレントディレクトリまたは上位ディレクトリに **`.jj/` ディレクトリが存在する**
2. **`jj root`** コマンドが正常終了（終了コード 0）する

> [!IMPORTANT]
> Git と共存している（colocated）リポジトリ（`.git/` と `.jj/` の双方が存在する環境）であっても、**`.jj` が検出された場合は Jujutsu (`jj`) を最優先** とします。

---

## 2. 行動原則 (Behavioral Rules)

1. **Jujutsu コマンドの最優先利用**:
   - 状態確認、差分確認、変更記録、履歴確認、ブランチ/ブックマーク操作などのあらゆるVCS操作において、`git` コマンドではなく `jj` コマンドを使用・提案してください。
2. **作業コピー（Working-copy commit）の理解**:
   - Jujutsu では作業ディレクトリの変更が常に自動的にコミット（デフォルトでは `@`）として追跡されます。
   - `git add` によるステージング操作は不要です。
3. **コミット・変更確定の手順**:
   - 変更内容の説明・メッセージ設定: `jj describe -m "<メッセージ>"`
   - 変更を確定して新しい作業を開始: `jj commit -m "<メッセージ>"` （または `jj describe -m "<メッセージ>" && jj new`）
4. **Git を使用する例外ケース**:
   - ユーザーが明示的に「Git で実行して」「git コマンドを使って」と指示した場合
   - Jujutsu 単体では扱えない Git 固有の機能（例: `git submodule update` など）

---

## 3. コマンド対応表 (Command Mapping)

| 操作内容 | Git コマンド | Jujutsu (`jj`) 推奨コマンド | 備考 |
| :--- | :--- | :--- | :--- |
| **状態確認** | `git status` | `jj status` (または `jj st`) | 作業コピーの変更状態と親リビジョンを表示 |
| **作業差分確認** | `git diff` | `jj diff` | 現在の作業コピー（`@`）の差分を表示 |
| **直前コミット差分** | `git diff HEAD~1` | `jj diff -r @-` または `jj show` | 親リビジョンの変更内容を表示 |
| **コミット/説明設定** | `git commit -m "..."` | `jj describe -m "..."` | 現在の作業リビジョンにメッセージを付与 |
| **コミット＆新規作業** | `git commit -m "..."` | `jj commit -m "..."` | メッセージを付与し、新しい空の作業リビジョンを作成 |
| **新規作業リビジョン作成** | なし（自動コミット） | `jj new` | 現在の変更の親上に新しい空リビジョンを作成 |
| **履歴・ログ確認** | `git log --oneline` | `jj log` | スマートログ（グラフ）を表示 |
| **変更の復元・取消** | `git restore <file>` | `jj restore <file>` | 親リビジョンの状態にファイルを復元 |
| **操作の取り消し** | `git reflog` + `reset` | `jj undo` | 直前の jj 操作そのものを取り消す（安全・強力） |
| **ブックマーク（ブランチ）**| `git branch <name>` | `jj bookmark create <name>` | ブックマーク（Gitブランチに相当）を作成 |
| **ブックマーク一覧** | `git branch` | `jj bookmark list` | ブックマーク一覧を表示 |
| **リモート取得** | `git fetch` | `jj git fetch` | リモートの変更を取り込み |
| **リモート送信** | `git push` | `jj git push` | リモート（Git）に変更をプッシュ |

---

## 4. クイックコマンドやレビュー時の適用

- **「レビュー」/「review」指示時**:
  - `.jj` が存在する場合、`git diff` ではなく **`jj diff`** を実行して変更差分を取得・レビューします。
- **ドキュメント・コミット提案時**:
  - ユーザーへ案内するコミット手順や操作ガイドには、`jj commit` / `jj describe` などの Jujutsu コマンドを第一候補として提示します。
