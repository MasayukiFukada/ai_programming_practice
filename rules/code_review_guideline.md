# コードレビューガイドライン (Code Review Guidelines)

AIエージェントおよび開発者がコードレビューを行う際の共通観点です。
以下の基準を満たしていないコードは修正を提案・実行してください。

## 1. アーキテクチャと凝集度
- Vertical Slice Architecture に従い、機能（ユースケース）に関連する処理が1つの場所にまとまっているか。
- 他の機能（コンテキスト）と密結合になっていないか。

## 2. 関数型アプローチとテスタビリティ
- 副作用（状態の変更、外部API呼び出し、DBアクセスなど）と、純粋なドメインロジック（計算、バリデーションなど）が分離されているか。
- 関数は単一責任であり、かつ十分に小さく保たれているか（CCN: 循環的複雑度が7以下を目安とする）。
- テストコードの作成が容易な構造になっているか。

## 3. 命名規則と可読性
- 変数名や関数名は、処理の意図を明確に表しているか（マジックナンバーや意味不明な略語がないか）。
- コメントは「何をしているか（What）」ではなく「なぜそうしているか（Why）」を説明しているか。

## 4. セキュリティとパフォーマンス
- 外部入力をそのまま信用せず、バリデーションを行っているか。
- メモリリークやN+1問題など、顕著なパフォーマンス劣化を引き起こす実装がないか。
- 秘密情報（APIキーやパスワードなど）がハードコードされていないか。
