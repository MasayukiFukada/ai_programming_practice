# AI時代のコーディング原則 (AI Coding Principles)

このプロジェクト（および本基盤を導入するプロジェクト）では、AIエージェントが効率的にコードを理解し、高品質な生成を行えるようにするための設計原則を定めます。
AIにとっての「コンテキストの肥大化」を防ぎ、テスタビリティの高い状態を維持することが重要です。

## 1. コンテキストの最小化 (Context Minimization)
AIが一度に理解すべきコード量（コンテキスト）を減らすため、以下の構造を徹底します。
- **Vertical Slice Architecture の採用**: レイヤーごとにファイルを分けるのではなく、機能（ユースケース）ごとにファイルを凝集させます。変更箇所が特定のディレクトリ内に収まるため、AIに与えるコンテキストが最小限になります。
- **単一責任原則**: 1つのファイル、1つの関数は1つのことだけを行うようにし、短く保ちます。

## 2. 関数型プログラミング (Functional Programming) の活用
状態（State）の変更はAIにとって追跡が難しく、バグの温床になります。オブジェクト指向の複雑な状態管理を避け、関数型アプローチを推奨します。
- **純粋関数 (Pure Functions)**: 入力のみに依存し、副作用のない関数を基本とします。これによりAIは関数の振る舞いを予測しやすくなります。
- **データの不変性 (Immutability)**: データを変更する場合は破壊的変更を避け、新しいオブジェクトを返すようにします。

## 3. テスタビリティ・ファースト (Testability First)
AIがコードを生成した直後に正しさを検証できるよう、テストしやすい構造を強制します。
- **依存性の分離**: 外部APIやデータベースへのアクセスなど、モックが必要な副作用のある処理は、純粋なドメインロジックから分離します。
- **テスト可能なコード生成**: エージェントが新規コードを生成する際は、原則として「テストコードも同時に、かつ容易に書ける設計」になっているかを自身で評価してから実装します。
