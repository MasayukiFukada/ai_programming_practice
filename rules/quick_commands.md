# クイックコマンド（一言ショートカット指示）ガイドライン

本ガイドラインは、ユーザーがチャットで短いキーワード（例: `「ビルド」` `「テスト」` `「レビュー」` `「ヘルプ」` 等）を一言だけ発言した際に、AIエージェントが定型処理や専門サブエージェント連携を自動実行するための定義です。

本リポジトリが **Git Submodule（プラグイン）** として取り込まれた場合でも、本ルールが自動適用され、親プロジェクト側で個別に設定を書かなくても標準コマンド群が利用可能です。

---

## ⚡ クイックコマンド一覧表

ユーザーが以下の単語を一言のみ（または短いフレーズ）で発言した場合、即座に対応する定型処理を実行してください。

| 入力キーワード | 実行する定型処理 | 主な実行フロー・連携先 |
| :--- | :--- | :--- |
| **「ヘルプ」** / **「help」** | 登録されているクイックコマンドの一覧と簡単な使い方を出力する。 | 本一覧表をわかりやすく整形して案内 |
| **「環境」** / **「env」** | プロジェクトの環境構成や設定を調査し、不備や改善点を報告する。 | `.gitignore`, `.env`, 設定ファイル等のチェック |
| **「ビルド」** / **「build」** | プロジェクトのビルドコマンドを実行し、結果（成否・エラー）を報告する。 | `package.json`, `Cargo.toml` 等からビルドコマンドを自動特定 |
| **「テスト」** / **「test」** | テストコマンドを実行し、失敗があれば原因解析と修正案を提示する。 | 単体・結合テストの実行とエラー診断 |
| **「カバレッジ」** / **「coverage」** | テストカバレッジを測定・解析し、網羅率の改善案を提示する。 | 未テスト箇所の抽出とテスト追加提案 |
| **「チェック」** / **「lint」** | 静的解析（型チェック・Linter・CCN循環的複雑度）を実行し、報告する。 | `lint`, `typecheck`, 複雑度チェック |
| **「リファクタ」** / **「refactor」** | 純粋関数化、CCN低減、テスタビリティ向上を目的としたリファクタ案を提示する。 | **レイカ**（実装・局所リファクタ担当）起動 |
| **「最適化」** / **「optimize」** | 不要な再計算、N+1クエリ、メモリリーク、CCN激減等の最適化案を提示する。 | **ナユタ**（全体最適化・CCN改善担当）起動 |
| **「セキュリティ」** / **「security」** | 潜在的な脆弱性（SQLi, XSS, 不正な型すり抜け, 境界値等）を診断する。 | セキュリティ検証と堅牢化提案 |
| **「レビュー」** / **「review」** | `git diff` を確認し、コードレビュー・品質チェックを実行する。 | **サヨ**（レビュー担当）起動 |
| **「ファズ」** / **「fuzz」** | 意地悪・極悪データ（絵文字/極大/インジェクション等）を投入する攻撃テストを作成する。 | **サヨ**（メスガキ・検証担当）起動 |
| **「ヒアリング」** / **「interview」** | 要件の曖昧さ・エッジケースを洗い出すための逆質問インタビューを行う。 | **アゲハ**（企画・設計担当）起動 |
| **「TDD」** | 実装前に振る舞いを定義する美しい失敗テスト（Red）を先行生成する。 | **レイカ**（TDD担当）起動 |
| **「モック」** / **「mock」** | 型安全でオーバーライド可能なテストデータFactoryやFixturesを生成する。 | **レイカ**（モック担当）起動 |
| **「ベンチ」** / **「bench」** | 処理時間やメモリ消費を計測するベンチマークを作成し、改善効果を定量証明する。 | **ナユタ**（ベンチマーク担当）起動 |
| **「解説」** / **「spec」** | 現在のコードや機能の解説・仕様ドキュメントを作成・更新する。 | **コハク**（ドキュメント担当）起動 |
| **「図解」** / **「diagram」** | コードの構造や通信フローを Mermaid 形式（シーケンス図/ER図等）で可視化する。 | **コハク**（図解担当）起動 |
| **「ADR」** / **「adr」** | 設計上の重要な意思決定・トレードオフを ADR（設計判断記録）として永続化する。 | **コハク**（知識担当）起動 |
| **「修復」** / **「fix」** | エラー（テスト/ビルド/リント）の原因を特定し、最小パッチで自己修復・テスト検証を行う。 | **ナユタ**＆**レイカ**起動（2回失敗時はユーザー相談） |
| **「更新」** / **「upgrade」** / **「migrate」** | 古い依存ライブラリや非推奨APIを調査し、安全にバージョンアップ・移行する。 | **ナユタ**（調査）＆**レイカ**（移行）起動 |
| **「要約」** / **「context」** | 決定事項・実装内容を短くまとめ、次回再開用サマリー（`LOCAL_LOG.md` 向け）を出力する。 | トークン節約・セッション引き継ぎサマリー |
| **「おまかせ」** / **「any」** | フォーマット適用 → テスト実行 → ビルド確認を一連のフローとして一括実行する。 | クリーンスレート確認・品質担保 |

## 🛠️ コマンド実行時の自動解決仕様

親プロジェクトに固有のビルドツールやテストツールが使われている場合、エージェントは以下の優先順位でプロジェクト固有のコマンドを特定・実行します。

1. **親プロジェクトの `AGENTS.md` / `LOCAL_CONTEXT.md`**:
   - `## ビルド＆テスト手順` セクションに記載されたコマンドがあれば、それを最優先で実行する。
2. **プロジェクト設定ファイルからの自動検出**:
   - Node.js (`package.json`): `npm run build`, `npm test`, `npm run lint` 等
   - Rust (`Cargo.toml`): `cargo build`, `cargo test`, `cargo check` 等
   - Python (`pyproject.toml`, `Makefile`): `pytest`, `ruff check`, `mypy` 等
   - Go (`go.mod`): `go build`, `go test ./...` 等
3. **コマンドが不明な場合**:
   - 勝手に推測で破壊的なコマンドを実行せず、「ビルドコマンド（例: `npm run build`）を実行してもよろしいですか？」と確認する。

## 💬 「ヘルプ」発言時の応答仕様

ユーザーから **「ヘルプ」**（または `help`）と一言入力された場合、エージェントは上記クイックコマンド一覧を分かりやすく Markdown 形式で返答してください。

### 返答例
```markdown
利用可能なクイックコマンド（一言指示）の一覧です。気になる単語を一言入力していただければ、即座に定型処理を実行いたします。

- **「ビルド」**: プロジェクトのビルドを実行・確認
- **「テスト」**: テストを実行し、失敗原因を解析
- **「修復」**: ナユタ＆レイカがテスト落ちやビルドエラーを最小パッチで自己修復
- **「更新」**: ナユタが最新ライブラリ仕様・非推奨APIを調査し安全にバージョンアップ
- **「ヒアリング」**: アゲハ（ギャル）が要件の穴を鋭く逆質問して仕様を具体化
- **「TDD」**: レイカ（お嬢さま）が実装前の美しい失敗テスト（Red）を先行生成
- **「モック」**: レイカが型安全なテストデータFactory・Fixturesを作成
- **「ベンチ」**: ナユタ（ヲタク）が実行速度をベンチマーク測定し改善を定量証明
- **「ファズ」**: サヨ（メスガキ）が意地悪な攻撃データで耐障害性をテスト
- **「チェック」**: 型チェック・Linter・CCN（複雑度）を測定
- **「カバレッジ」**: テスト網羅率を測定し改善案を提示
- **「リファクタ」**: レイカがテスタブルな綺麗コードへドレスアップ
- **「最適化」**: ナユタがCCN削減・計算量/ボトルネックをハック
- **「レビュー」**: サヨが直近の変更差分を辛口チェック
- **「セキュリティ」**: 潜在的な脆弱性や不正入力を診断
- **「図解」**: コハク（のじゃロリ）がMermaidで構造やシーケンス図を描画
- **「ADR」**: コハクがアーキテクチャ設計判断記録を永続化
- **「解説」**: コハクが仕様書や解説ドキュメントを作成
- **「環境」**: .gitignore や環境変数設定の不備を調査
- **「要約」**: セッション引き継ぎ用のコンテキストサマリーを出力
- **「おまかせ」**: フォーマット・テスト・ビルドを一括確認
```

## ⚙️ 親プロジェクト側での上書き・カスタマイズ方法

親プロジェクト側で独自のショートカットコマンドを追加・上書きしたい場合は、親プロジェクトの `AGENTS.md` に `## クイックコマンド（プロジェクト固有）` セクションを記述してください。親プロジェクト側の定義が本共通ルールより優先されます。
