# 能動的モデル活用＆サブエージェント協調戦略 (Active Model Tier & Subagent Collaboration Strategy)

本ルールは、強力な最新モデル群を適材適所で最大限に活用し、コンテキスト汚染を防ぎながら開発の品質と速度を飛躍させるための**能動的サブエージェント委譲・モデル階層戦略**を定めます。

---

## 1. 基本思想：親エージェントは指揮官（オーケストレーター）

- **親エージェントの役割**:
  ユーザーとの対話、要件・方針の整理、タスクの分解、サブエージェントの統括（オーケストレーション）に徹します。
- **能動的なタスク委譲 (Active Delegation)**:
  すべての作業を親エージェント単独の単一コンテキストで抱え込まず、**「調査」「実装」「レビュー」などの専門フェーズごとに、最適なモデルとペルソナを持つサブエージェントへ積極的に仕事を割り振ります**。
- **コンテキスト分離の恩恵**:
  サブエージェントに作業を委譲することで、大量のファイル走査や試行錯誤が親コンテキストを圧迫・汚染するのを防ぎ、常にクリアで高品質な判断を維持できます。

---

## 2. タスク別の能動的委譲マッピング

| タスクフェーズ | 推奨サブエージェント | 推奨モデル | 委譲の目的とメリット |
| :--- | :--- | :--- | :--- |
| **広範なコード調査・探索** | `self` (ナユタ通常) / `research` | **`flash_lite`** / **`flash`** | 大量のファイル読み取りやキーワード検索をオフロード。親のコンテキストを汚さず高速に要点を特定。 |
| **中核実装・リファクタ** | `self` (レイカ) | **`pro`** | 最高峰の推論能力（Proモデル）を活用し、エッジケースまで考慮した堅牢でエレガントなコードを一発で生成。 |
| **日常コードレビュー（都度確認）** | `self` (サヨ) | **`flash`** / **`inherit`** | クォータを消費せず高速に差分検証。文法、タイポ、単一責任、基本テストを即座にチェック。 |
| **厳格レビュー・セキュリティ診断** | `self` (サヨ) | **`pro`** (Argon等) | マージ直前や「本気レビュー」「セキュリティ」指定時。独立コンテキストで潜伏バグや認可バイパスを徹底検証。 |
| **全体最適化・CCN削減** | `self` (ナユタ) | **`pro`** (Argon等) | 依存関係グラフのトポロジー解析、計算量次元削減、循環参照解消などの高度な抽象思考をProで遂行。 |
| **ドキュメント・図解整理** | `self` (コハク) | **`flash`** / **`inherit`** | 確定したコードベースからADRやMermaid図解を高速・綺麗に作成。 |

## 3. モデル階層（Model Tiers）と引数指定

Antigravity の `invoke_subagent` ツールにおける `Model` 引数は、タスクの複雑度に応じて**意図的に指定**します（無指定の `inherit` に頼りすぎず、モデルの得意領域を引き出します）。

```markdown
invoke_subagent:
  TypeName: 'self' (または 'research')
  Role: 'Implementation Engineer'
  Model: 'pro' | 'flash' | 'flash_lite' | 'inherit'
  Prompt: ...
```

### ① Lightweight / Fast (`Model: 'flash_lite'`)
- **得意分野**: 定型的なフォーマット変換、型定義のみの機械的抽出、高速ファイル存在確認
- **効果**: 爆速の応答性と極小トークン消費

### ② Standard / Balanced (`Model: 'flash'` / `'inherit'`)
- **得意分野**: ドキュメント作成、一般的なコードベース探索（`research`）、一般的なユニットテスト作成
- **効果**: 高速性と精度の優れたバランス

### ③ High-Reasoning / Flagship (`Model: 'pro'`)
- **得意分野**:
  1. 複雑なビジネスロジックの新規実装・テスタブルリファクタ
  2. 6大観点に基づいた厳密なコードレビュー・セキュリティ脆弱性検証
  3. 複雑度（CCN）の大幅削減、アルゴリズムの計算量最適化
  4. **エラー連続時の自己修復（Two-Strike Escalation）**: 同一エラーで2回失敗した場合は即座にProへエスカレーションして根本原因を特定

## 4. 委託・引き継ぎ時のプロトコル (Handover Protocol)

サブエージェントを起動する際は、`rules/prompt_caching_guideline.md` のキャッシュ設計に基づき、プロンプトを以下の構造で渡します：

1. **静的コンテキスト（先頭）**: プロジェクトの基本制約（VSA、コーディング原則）
2. **達成すべき明確なゴール**: 何を作れば/検証すれば完了かの受け入れ基準
3. **対象ファイル・範囲の限定**: レビューや実装のスコープ（不要な広域探索の防止）
4. **ペルソナ指定（末尾）**: 担当キャラクターの行動規範・口調の指定

---

## 5. レビューにおける「コンテキスト分離」とクォータ保護の原則

**「自分で書いたコードを、同じプロンプトの続きで自分でレビューする」のは自己バイアス（盲点）を生む最大の原因です。**
一方で、レビューのたびに無制限にハイエンドモデル（Pro / Argon）を起動すると、**貴重な推論クォータが即座に枯渇するリスク**があります。

そのため、レビューは以下の **2段階（Tiered Review）運用** を徹底します：

1. **日常レビュー（デフォルト: `flash` / `inherit`）**:
   - クイックコマンド（「レビュー」「review」「チェック」）やコミットごとの細かな確認は、**高速かつクォータ消費実質ゼロの Flash** でサヨを起動。
   - 1日に何十回実行してもクォータ制限に引っかからず、開発テンポを最大化。
2. **厳格ディープレビュー（明示指定時: `pro` / Argon）**:
   - ユーザーが「厳密レビュー」「本気レビュー」「セキュリティ診断」と指示した場合、またはブランチのマージ直前ゲート時のみ、**`pro`（Argon等）** を起動。
   - 独立したクリーンなコンテキストで、潜在脆弱性・エッジケース・CCN・Mantis型検証を徹底的に遂行。

---

## 6. コード探索におけるグラウンディング（証拠主義）と2段階エスカレーション

コードベースの探索・リサーチを軽量モデル（`flash_lite` / `flash`）で行う際は、ハルシネーション（推測による事実歪曲）を防ぎつつトークン消費を最小化するため、以下のプロトコルを徹底します：

1. **フェーズ1：最軽量モデルによる事実調査（ナユタ通常モード / `flash_lite`）**:
   - **推測の完全禁止**: 「おそらくこう動いている」などの推論や仮説を一切排除し、コード上の事実のみを報告。
   - **厳格なグラウンディング**: 報告するすべての事実について、`ファイルパス#L開始-L終了` と実際の実装コード抜粋の提示を義務付ける。
   - **早期ギブアップ（未発見時の即時終了）**: 検索で該当箇所が特定できない場合、推測で補完せず「該当する実装は見つかりませんでした」と報告して完了する。
2. **フェーズ2：未発見・複雑依存時のエスカレーション（`pro`）**:
   - フェーズ1で未発見だった場合、または「複数ファイルを跨ぐ複雑なライフサイクル追跡」「動的ディスパッチの解読」が必要な場合のみ、`Model: 'pro'`（または親エージェント）へエスカレーションして詳細な推論解析を行う。
