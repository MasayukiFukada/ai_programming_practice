# エージェント・モデル階層運用ルール (Model Escalation Strategy)

本ルールは、日々の開発においてレスポンスの俊敏性とコスト効率を維持しつつ、難関タスクやバグ修正の泥沼化（無限ループ・パッチ当て繰り返し）を防止するための**動的エスカレーション運用指針**を定めます。

---

## 1. 基本方針 (Default: Standard / Balanced)

- **原則**: 通常の実装、テスト作成、一般的な調査・ドキュメント作成などの日常タスクは、**標準モデル（Standard / Balanced / 例: `inherit` または `flash`）**で実行します。
- **目的**: 軽快なターンアラウンドを維持し、トークン消費とレスポンス遅延を抑えて開発テンポを最大化します。

---

## 2. 高度推論モデル (High-Reasoning / Flagship) への昇格基準

以下のいずれかの条件を満たした場合、現在のエージェント単独での安易な試行を直ちに中止し、**高度推論モデル（High-Reasoning / Flagship / 例: `invoke_subagent` の `Model: 'pro'`）**のサブエージェントへタスクを委託（エスカレーション）します。

### ① 2回連続失敗（Two-Strike Escalation）
- 同一のテスト落ち、ビルドエラー、デバッグにおいて、**2回の修正試行を経ても解決しなかった場合**。
- **禁止事項**: 3回目以降の「もう一度修正してみます」という場当たり的なパッチ当ての継続。コンテキストが不要な試行錯誤で汚染される前に、即座に上位モデルへ切り替えて根本原因を分析させます。

### ② 難解タスクの検知（Inherent Complexity）
着手時点で以下のいずれかに該当すると判断した場合、最初から高度推論モデルを指名して実行させます。
- **大規模アーキテクチャ設計**: 複数モジュールを横断する責務分割、データフロー再設計
- **複雑度・アルゴリズム最適化**: 循環的複雑度（CCN）の大幅削減（例: CCN 20超の怪物の解体）、計算量次元削減（$O(N^2) \to O(N)$ など）
- **高度なセキュリティ・堅牢性診断**: 認可・権限バイパス検証、潜在的な暗黙インジェクション脆弱性の網羅的解析

---

## 3. 委託時の引き継ぎプロトコル (Handover Protocol)

高度推論サブエージェントへタスクをエスカレーションする際は、同じ轍を踏ませないために以下の3点をプロンプトに集約して渡します：

1. **達成すべき明確なゴール**（仕様・受け入れ基準）
2. **発生している問題 / 直面したエラーの詳細**（ログ・スタックトレース）
3. **これまでに試した2回のアプローチと失敗理由**（不要な堂々巡りの防止）

---

## 4. 汎用モデル階層と環境別マッピング (Tier Mapping)

ベンダーやツール（Gemini, Claude, OpenAI, Antigravity, Cursor等）に依存しないよう、ルール記述には以下の汎用Tierを用い、実行環境のツール引数や設定値へマッピングします。

| 汎用階層（Tier） | 役割・用途 | Antigravity (`invoke_subagent`) | 代表的モデル例 |
| :--- | :--- | :--- | :--- |
| **Lightweight / Fast** | 単純作業、フォーマット変換、一次調査 | `flash_lite` | Gemini Flash-Lite / Claude Haiku / GPT-4o-mini |
| **Standard / Balanced** | 通常の実装、テスト、レビュー、ドキュメント | `inherit` または `flash` | Gemini Flash / Claude Sonnet / GPT-4o |
| **High-Reasoning / Flagship** | 2回失敗時、CCN削減、難関設計、深層診断 | `pro` | Gemini Pro / Claude Opus / OpenAI o-series |

---

## 5. キャラクターペルソナとの連動

本リポジトリのペルソナ（`character_personas.md`）と併用する場合、以下の対応関係でエスカレーションを行うとより効果的です：

- **通常実装・テスト（Standard）**: レイカ（実装担当）、サヨ（通常レビュー）
- **高度推論エスカレーション（High-Reasoning）**:
  - エラー泥沼化・自己修復: ナユタ（根本原因特定 / `self_heal_error`）
  - CCN激減・アーキテクチャ大改修: ナユタ（マッドギーク覚醒モード / `optimize_complexity`）
  - 複雑な論理設計・要件深掘り: アゲハ（冷静ツッコミ / `interview_requirements`）
